# Main API python module

This service defines TaskIQ workers for managing VPN subscriptions, client balances, and transactions. 
It uses `peerhub` tasks to manage VPN connections.

This module: `shiro.main_api`.

# Broker

Module: `.broker`.

Broker configs:

| Name                           | Fields                                                       |
| ------------------------------ | ------------------------------------------------------------ |
| `MainApiBrokerConfigForClient` | `broker_url: AmqpDsn`<br/>`result_backend_url: RedisDsn`<br/>`exchange_name: str` (default `main_api_exchange`) |
| `MainApiBrokerConfigForWorker` | `MainApiBrokerConfigForClient`<br/>+ `queue_name: str` (default `main_api_queue`) |

IMPORTANT: call `.broker.define_main_api_broker_as_client` (a service that only kicks `main_api` tasks) or `.broker.define_main_api_broker_as_worker` (the process that consumes `main_api_queue`) before importing `.tasks`.

`TelegramID`, `TelegramUsername` and `Money` are shared pydantic aliases from `shiro.util.types`: a Telegram id ($\ge 0$, $\lt 2^{63}$), a Telegram @username (`[A-Za-z0-9_]{1,32}`, without `@`) and a positive ruble amount with at most two decimals. `PaymentStatus` is `PENDING` | `CONFIRMED` | `CANCELED` | `CHARGEBACKED`, the string `main_api.check_payment` answers with.

`PaymentPost.return_callback` is the bot's own data: it comes back untouched in `telegram_bot.notify_topup`.

`BackendStats.usage` is read from the nodes' live counters, not a history: a node that does not answer is counted in `hubs_failed` and its peers report nothing.

`WgConfig` and `XuiConfig` are `shiro.peerhub.models`. A wg-easy peerhub answers with `{config}` (the `.conf` body), a 3x-ui peerhub with `{sub_url}`; the union never mixes them, because taskiq sends the result as JSON primitives and the reader validates the shape it got.

# Exceptions

Module: `.exceptions`

Custom business exceptions raised by tasks. All inherit from `AppException`, and each `error_code` is a member of `shiro.util.errors.ErrorCode`. taskiq does not send the exception object: it rebuilds the class on the caller's side from `exc_module`, `exc_type` and `exc_args`, so a `ClassVar` does not travel — read the code with `shiro.util.errors.error_code_of(error)`, which tries the message first (`AppException.__init__` puts `error_code` into `args`) and the class name second.

| Name                                 | Description                                                                                                             | Error code                           | Status code | How and where can rise?                                                                                                           |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ----------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `client_exists`                      | Client with given Telegram ID already exists.                                                                           | `CLIENT_EXISTS`                      | 499         | `main_api.post_client`                                                                                                            |
| `client_not_found`                   | Client with given Telegram ID does not exist.                                                                           | `CLIENT_NOT_FOUND`                   | 498         | Almost every task.                                                                                                                |
| `client_already_activated_trial`     |                                                                                                                         | `CLIENT_ALREADY_ACTIVATED_TRIAL`     | 497         | `main_api.post_trial_subscription`                                                                                                |
| `client_did_not_activate_trial`      |                                                                                                                         | `CLIENT_DID_NOT_ACTIVATE_TRIAL`      | 496         | –                                                                                                                                 |
| `subscription_exists`                | Client has a subscription (sub is not marked deleted in DB).                                                            | `SUBSCRIPTION_EXISTS`                | 495         | `main_api.post_trial_subscription`                                                                                                |
